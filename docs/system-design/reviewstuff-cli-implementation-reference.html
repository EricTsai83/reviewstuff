1. 使用者能完成什麼

目前的主要使用者是站在本機 Git repository 裡的開發者。CLI 提供兩個實際可觀察的 review scope：預設的 working-tree review 會檢視相對 HEAD（沒有首個 commit 時則相對 empty tree）的 tracked 淨變更，再合併 untracked files；--staged 則只檢視 index。 CLI 不修改 repository，也沒有 upload 或 session store。

Review pipeline 不是單純把整份 diff 塞進 engine。它先正規化 Git metadata 與完整 hunks，排除 binary，再按 path/source 排序，以 round-robin 方式逐輪選取每個檔案的一個完整 hunk，直到 request budget 用完。結果會明確記錄 reviewed、truncated、skipped 與 budget 數字。

信心邊界 本報告把 runtime wiring、source implementation、schemas 與 executable tests 視為現況證據。plans/ 中尚未完成的 OpenAI、privacy、persistence、 doctor 與 release 工作只代表設計意圖，沒有被列成現行能力。

6. Domain 與資料設計

中央概念

主要 domain values 與 invariants
Concept Owner Invariant / lifecycle Used by
ReviewScope domain/scope.ts 只有 working-tree 或 staged CLI selection、Git collection、request 與 report
GitDiff / GitFile git/git-diff.ts 每個 file 是 text（完整 header/hunks）或 binary；保留 status/rename metadata budget selection 與 coverage
ReviewSelectionV1 review/review-budget.ts 只選 complete hunks；每個 file 得到 reviewed/truncated/skipped；總額不可超 budget engine request 與 report coverage
ReviewRequestV1 review/review-request.ts repository data 標成 untrusted；只含 engine 所需資料，不含 timeout/concurrency ReviewEngine.review
ReviewFindingV1 domain/finding.ts non-empty identity/rule/message/file、positive line、固定 severity/category、confidence 0–1 engine output、report、terminal/JSON
ReviewReportV4 domain/report.ts summary counts 必須等於 contents；coverage.complete 與 statuses 一致；file identity 不重複；budget arithmetic 一致 CLI current output

現行沒有 database schema、migration 或 aggregate persistence。ReviewReportV2 與 V3 到 V4 的 migrations 是 serialization compatibility utilities；CLI 只產生 V4，也沒有 runtime path 讀取歷史 report。

Consistency boundary

一次 review 是 read-only、in-memory、best-effort 的單 process flow，不存在 database transaction。Git metadata 和逐檔 patch 之間 repository 仍可能改變；實作會把消失的 changed file 映射成 GitChangedFileUnavailableError 並整次失敗。成功 report 是該次讀取的自我一致 schema value，但不是 repository 的 atomic snapshot。

Scenario：開發者 review 整個 working tree

Actor
本機開發者
Goal
查看尚未 commit 的 net changes 與 finding/coverage
Trigger
reviewstuff review
Preconditions
cwd 位於有 working tree 的 Git repository；config 可解碼；selection 是 fake
Success
terminal 或 V4 JSON report；無 changes 時明確顯示 no changes
Mutation
沒有 repository mutation；只產生 process output

User-visible flow

  1. 開發者執行 review；可從 repository 的 nested directory 呼叫。
  2. 系統解析設定，確認目前 build 支援所選 engine/provider/model。
  3. 系統找 repository root，收集相對 HEAD 的 tracked net diff 及 untracked files；初始 repository 改用 empty tree。
  4. binary files 進 coverage 但不送 engine；text hunks 按 budget 選取。
  5. fake engine 只為新增行中的 marker 產生 deterministic findings，系統組裝並 render report。

System implementation

Working-tree review 的 end-to-end hops
User step System behavior Domain / data effect Evidence
執行 review flags decode，未給 --staged 時選 workingTreeScope 建立 RunReviewInput review.ts:84–113
套用設定 讀 cwd config，依 precedence resolve，再拒絕非 fake selection ResolvedReviewConfig run-review.ts:178–184
讀取變更 檢測 work tree、root、conflicts；並行收 tracked 與 untracked patches GitDiff git-service.ts:254–330
限制 request 只取 text files，以 sorted round-robin 選 complete hunks ReviewSelectionV1 + coverage + estimate review-budget.ts:184–330

Alternative and failure paths

  • 無 changes：成功、terminal 顯示 No changes to review.，JSON 仍是完整 V4 report。
  • 不是 repository、bare/no work tree、unmerged paths：失敗 exit 1，stderr 提供對應 guidance。
  • Git timeout、output cap、invalid output、changed file 在讀取中消失：整次失敗，不產生 partial report。
  • 沒有任何 hunk 能放入 budget：engine 不被呼叫，仍成功產生 incomplete coverage report。
  • 流程是 read-only；解決衝突、權限、lock 或 repository race 後可安全重試。

Dependencies

Bun filesystem、Effect child-process runtime、local git executable、 yaml parser、repository-root .reviewstuff.yaml（optional） 與 fake ReviewEngine。沒有 network、 database 或 queue。

Evidence and confidence

Verified runtime chain 有 source wiring，且 test/e2e/cli.e2e.test.ts:306–347, 388–561 以 temporary repositories 驗證 staged + unstaged + untracked、renames、literal paths、 budget 與 binary coverage。Git 細節另見 Git pipeline implementation reference。

Scenario：開發者解析 review 設定

Actor
開發者或 repository config author
Goal
選擇 preset 與執行 budget
Trigger
執行任何 review command
Success
取得完整 ResolvedReviewConfig

User-visible flow

  1. GitService 先從 cwd 或 --dir 解析 canonical working-tree root；ConfigService 只讀該 root 的 .reviewstuff.yaml。
  2. YAML 1.2 parser 先拒絕 duplicate keys、tags、anchors、aliases、merge keys、multiple documents 與非 JSON-compatible values。
  3. parser output 視為 unknown，再由 Effect Schema strict decode；unknown properties、empty strings、non-positive timeout/concurrency 都失敗。
  4. 先選 quick/standard preset defaults，再覆蓋 file values，最後覆蓋 CLI flags。
  5. 目前只有完整的 fake/fake/fake-reviewer-v1 tuple 可進入 Git work；其他 selection 明確失敗。

Precedence

selected preset defaults → .reviewstuff.yaml review object → CLI overrides。 quick 與 standard 的 model/budget 相同，但 quick 是 30s / concurrency 1，standard 是 120s / concurrency 2。

Alternative and failure paths

  • 檔案不存在、blank 或 comment-only：採 standard defaults。
  • 讀檔 permission failure：ConfigFileReadError，exit 1。
  • YAML syntax 或 feature rejection：ConfigFileParseError，包含安全的 line/column。
  • typed config invalid：ConfigFileSchemaError，只顯示白名單 field path 與安全 constraint，不包含 rejected value、raw config、cause 或 stack。
  • reviewstuff.config.json、.reviewstuff.yml 與其他 aliases 完全不載入。
  • nested cwd 與 --dir 都讓 config 和 reviewed diff 共用同一個 canonical repository context。

Evidence and confidence

Verified src/config/yaml-parser.ts； src/config/config-service.ts； test/config/yaml-parser.test.ts； test/config/config-service.test.ts； test/e2e/cli.e2e.test.ts。

Scenario：開發者或 script 消費 review report

Actor
人類開發者或 automation caller
Goal
理解 findings、coverage 與 request budget
Trigger
review 成功；可選 --json
Success
human-readable text 或 strict ReviewReportV4

Rules

  • Terminal finding 顯示 file:line、severity/category、confidence、message 與 ruleId。
  • coverage 不完整時，列出 truncated/skipped files 與 request-budget/binary/file-too-large reason。
  • terminal 中所有 repository/engine controlled strings 會 escape control characters；JSON 則保留資料並交由 JSON escaping。
  • report schema 驗證 summary counts、coverage completeness、unique identity、hunk counts 與 budget arithmetic。

State transitions

沒有 persisted lifecycle。資料只從 GitDiff → ReviewSelectionV1 → ReviewRequestV1 + findings → ReviewReportV4 → rendered bytes 轉換。

Important limitation

findings 數量與 incomplete coverage 目前不改變 process 成功狀態；只有 pipeline error 由 command handler 設 process.exitCode = 1。Automation 必須解析 JSON 才能依 finding/coverage 做 gate。

Evidence and confidence

Verified src/domain/report.ts:117–201； src/output/report-renderer.ts:38–89； test/output/report-renderer.test.ts。
