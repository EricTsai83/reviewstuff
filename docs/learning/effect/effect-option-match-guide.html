Effect Option.match：一次處理有值與無值

Option.match 接收一個 Option<A>，分別處理 Some 與 None，最後產生一個普通值。當兩種情況需要不同邏輯時，它是最直接、完整的出口。

版本基準：effect@4.0.0-beta.98

先理解 Option 表達什麼

在 Effect 裡，Option<A> 表示「可能存在一個 A」。它只有兩種狀態：

狀態 意義 Option.match 執行的分支
Some(value) 有值 onSome(value)
None 沒有值 onNone()

Option.match 的工作，就是確認目前是哪一種狀態，執行對應函式，再把該函式的結果回傳。它不會同時執行兩個分支。

一個完整例子

假設系統找到的顯示名稱是 Option<string>。畫面最終需要普通字串，所以有值時顯示名稱，沒有值時顯示訪客文案：

TypeScriptimport { Option } from "effect"

const displayName = Option.some("Eric")

const greeting = Option.match(displayName, {
  onNone: () => "歡迎，訪客",
  onSome: (name) => `歡迎，${name}`,
})

console.log(greeting) // "歡迎，Eric"

如果把輸入換成 Option.none()，結果就會是 "歡迎，訪客"。

把它想成一個有回傳值的 if / else

下面兩段程式的核心語意相同：

TypeScriptconst greeting = Option.match(displayName, {
  onNone: () => "歡迎，訪客",
  onSome: (name) => `歡迎，${name}`,
})
TypeScriptconst greeting = Option.isNone(displayName)
  ? "歡迎，訪客"
  : `歡迎，${displayName.value}`

match 的好處不是它能做到 if / else 做不到的事，而是它把兩個分支放在同一個表達式裡，並讓 Effect 的型別定義負責傳遞 Some 裡的值。

也能放進 pipe

Option.match 支援 Effect 常見的 dual API，因此既能採用前面的 data-first 寫法，也能採用 data-last 的 pipe 寫法：

TypeScriptconst greeting = displayName.pipe(
  Option.match({
    onNone: () => "歡迎，訪客",
    onSome: (name) => `歡迎，${name}`,
  }),
)

兩種寫法沒有語意差異；選擇與周圍程式碼最一致的形式即可。

回傳型別由兩個 callback 決定

Option.match 不保證回傳字串，也不會自動回傳另一個 Option。它的結果就是 onNone 或 onSome 的結果。

TypeScriptconst result = Option.match(Option.some(3), {
  onNone: () => "missing",
  onSome: (value) => value * 2,
})

// result 的型別是 string | number
// runtime 結果是 6

兩個分支可以回傳不同型別，此時 TypeScript 會推導為 union。不過在應用程式邊界，讓兩個分支回傳相同種類的結果通常更容易使用。

onNone 是 lazy 的

onNone 接受函式而不是現成值。只有輸入真的是 None 時，這個函式才會被呼叫；昂貴的 fallback 計算不會在 Some 情況下白做。

與 map、getOrElse 怎麼選

需求 較直接的 API 結果
只轉換現有值，沒有值就維持沒有值 Option.map 仍是 Option
有值就取值，沒有值只需要一個預設值 Option.getOrElse 普通值
Some 與 None 各有一套處理邏輯 Option.match 普通值或 callback 指定的型別

只需要 fallback 時，不必使用 match

TypeScriptconst name = displayName.pipe(
  Option.getOrElse(() => "訪客"),
)

這比「onSome 原樣回傳、onNone 給預設值」的 match 更直接。

還要繼續做 Option 運算時，不要太早 match

TypeScriptconst normalizedName = displayName.pipe(
  Option.map((name) => name.trim().toUpperCase()),
)

這裡保留 Option 比立刻轉成普通值更有用。通常等到 UI、日誌或其他必須產出具體結果的邊界，再用 match 收尾。

不要和 Match 模組混淆

Option.match 固定處理 Option 的 Some／None。Effect 的 Match 模組則是更通用的 pattern matching 工具，可處理 tagged union、結構化 pattern 與完整性檢查。名稱相近，但用途與抽象層次不同。

一句話決策

當你需要從 Option 走出來，而且「有值」與「沒有值」各自需要明確邏輯，就使用 Option.match；若只是轉換值或提供預設值，優先考慮更窄、更能表達意圖的 Option.map 或 Option.getOrElse。
